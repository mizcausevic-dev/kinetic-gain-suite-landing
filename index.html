Open governance protocols
for the agent era.

A family of eleven open JSON specifications for declaring what an AI system is, what it does, what it refuses, what evidence it carries, what regulatory class it falls under, and what happens when it fails. Five core specs · two regulated-vertical extensions (EdTech, HealthTech) · two cross-cutting specs (incident + procurement decision). One MCP server, one hosted validator, 22 live subdomains. Specs MIT, reference implementations AGPL-3.0.

The suite at a glance

Each spec carries a top-level <name>_version field. The unified visualizer auto-detects which spec a document is in by inspecting that field. The MCP server exposes fetch / validate / inspect / cross-spec-join tools for all eleven specs.

Two front doors

The hosted validator is the buyer-side entry point — paste a vendor's JSON, get a procurement-grade report. The unified MCP server is the agent-side entry point — every spec becomes a callable tool. Ten specs, two front doors.

VALIDATOR · web

validator.kineticgain.com

Paste any Suite JSON in the browser and get a procurement-grade validation report. Auto-detects which of the eleven specs the document belongs to via its *_version field, then validates against the canonical JSON Schema 2020-12. Errors surface as inline markers in a Monaco editor with line numbers.

open https://validator.kineticgain.com
  • 10 schemas bundled — no network at validation time
  • Inline error markers with jump-to-line
  • Companion: full React visualizer with 10 procurement-grade renderers

MCP SERVER · stdio

mcp-kinetic-gain

47 tools across all 11 specs, v0.5.2, published on npm with provenance. One Claude Desktop / Cursor / MCP-client config entry. Two headline cross-spec tools: aup_check_compliance (AUP + Student AI Disclosure → allow/deny) and incident_index_fetch (aggregates a vendor's public incident registry). v0.5.2 adds AI Procurement Decision Card support (buyer-side artifact) on top of v0.5.1's CLI mode.
